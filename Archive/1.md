# 📘 الملخص الشامل والموحد لإدارة المستخدمين والصلاحيات في MySQL

---

## 📌 الجزء الأول: عن ماذا يتكلم المقال؟

المقال المأخوذ من موقع [DigitalOcean](https://www.digitalocean.com/community/tutorials/how-to-create-a-new-user-and-grant-permissions-in-mysql#2-how-do-i-check-mysql-user-permissions) بعنوان **"How to Create a MySQL User and Grant Privileges"** هو دليل تعليمي يشرح كيفية إدارة المستخدمين والصلاحيات في قاعدة بيانات MySQL على سيرفر يعمل بنظام Ubuntu.

### المحاور الأساسية للمقال:
1. **طرق تسجيل الدخول بحساب الـ Root:** الفرق بين التوثيق بـ `auth_socket` والتسجيل بكلمة المرور.
2. **إنشاء مستخدم جديد (`CREATE USER`):** استخدام إضافات التوثيق مثل `caching_sha2_password` و `mysql_native_password`.
3. **منح الصلاحيات (`GRANT`):** تحديد صلاحيات مثل `CREATE`, `ALTER`, `DROP`, `INSERT`, `UPDATE`, `DELETE`, `SELECT`, `REFERENCES`, و `RELOAD`.
4. **تحديث الصلاحيات وإدارة الحسابات:** التعرف على أمر `FLUSH PRIVILEGES` وكيفية حذف الحسابات (`DROP USER`) أو سحب الأذونات (`REVOKE`).

## 📑 الجزء الثاني: الأسئلة والشروحات التفصيلية

---

### 1️⃣ معرفة الحساب الحالي والفرق بين مستخدم النظام ومستخدم MySQL
* **معرفة مستخدم MySQL:** يتم باستعلام `SELECT USER(), CURRENT_USER();`.
* **معرفة مستخدم النظام:** يتم في التيرمنال عبر `whoami`.
* **رؤية الحسابات وطرق توثيقها:** `SELECT User, Host, Plugin FROM mysql.user;`.
* **حسابات الصيانة:** وجود حسابات مثل `debian-sys-maint` أو `mysql.sys` أمر طبيعي جداً في نظام Ubuntu؛ فهي حسابات صيانة داخلية ينشئها النظام تلقائياً ولا تعني وجود أي مشكلة أمنية.

---

### 2️⃣ أمر `sudo` وآلية عمله
* **المفهوم:** اختصار لـ *(SuperUser DO)*، يعطي المستخدم العادي صلاحيات المدير الخارق *(Root)* لتنفيذ أمر محدد.
* **آلية العمل:** يتحقق النظام من إذن المستخدم، يطلب كلمة مرور حساب Linux الخاص به، يرفع معرّف العملية مؤقتاً إلى `UID 0` (صلاحية Root)، وينفذ الأمر مع تسجيله في ملف السجلات (`auth.log`).

---

### 3️⃣ آلية التوثيق عبر `auth_socket` والعلاقة بين الحسابات
* حساب مستخدم Linux وحساب MySQL هما حسابان منفصلان.
* عند كتابة `sudo mysql`: تمنحك `sudo` صلاحية root نظام التشغيل مؤقتاً، فتقرأ إضافة `auth_socket` في MySQL هذا الطلب وتسمح بالدخول لحساب `root` بـ MySQL تلقائياً دون كلمة مرور.

---

### 4️⃣ الفرق بين صلاحيات الـ Client وصلاحيات الأدمن داخل MySQL
* عند تشغيل `mysql -u root -p` بدون `sudo` فأنت تشغل برنامج الـ Client كمستخدم عادي في Linux.
* بمجرد إدخال كلمة سر الـ root الخاصة بـ MySQL، يتأكد السيرفر من هويتك ويمنحك **صلاحيات أدمن كاملة داخل بيئة MySQL فقط** دون رفع صلاحياتك بداخل نظام التشغيل Ubuntu نفسه.

---

### 5️⃣ جدول الصلاحيات الأساسية في MySQL

| الصلاحية | مثال SQL | الوظيفة |
| :--- | :--- | :--- |
| **`CREATE`** | `CREATE DATABASE my_db;` | إنشاء قواعد بيانات أو جداول جديدة. |
| **`ALTER`** | `ALTER TABLE users ADD age INT;` | تعديل هيكل جدول قائم. |
| **`DROP`** | `DROP TABLE users;` | حذف جداول أو قواعد بيانات. |
| **`INSERT`** | `INSERT INTO users VALUES (...);` | إضافة صفوف وبيانات جديدة. |
| **`UPDATE`** | `UPDATE users SET name='Ali';` | تعديل البيانات الموجودة. |
| **`DELETE`** | `DELETE FROM users WHERE id=1;` | حذف صفوف محددة. |
| **`SELECT`** | `SELECT * FROM users;` | قراءة وعرض البيانات. |
| **`REFERENCES`** | `FOREIGN KEY ... REFERENCES` | إنشاء علاقات الربط بين الجداول (Foreign Keys). |
| **`RELOAD`** | `FLUSH PRIVILEGES;` | إجراء عمليات تفريغ الذاكرة وإعادة تحميل السجلات. |

---

### 6️⃣ تفاصيل عمليات التفريغ (`FLUSH Operations`)

1. **`FLUSH PRIVILEGES;`**
   * يجبر السيرفر على إعادة قراءة جدول الصلاحيات (`Grant Tables`) المكتوب بالقرص الصلب وتحديث الذاكرة العشوائية (RAM) به.
2. **`FLUSH LOGS;`**
   * يغلق ملفات السجلات الحالية ويفتح ملفات جديدة فارغة مع زيادة الرقم التسلسلي في نهاية اسم الملف (مثل `mysql-bin.000002`).
3. **`FLUSH TABLES WITH READ LOCK;`**
   * يجبر الخادم على كتابة كافة البيانات المعلقة بالذاكرة إلى القرص الصلب ويغلق الجداول مؤقتاً بقفل قراءة لضمان عدم حدوث **نسخة احتياطية تالفة (Corrupted Backup)**.

---

### 7️⃣ جدول الصلاحيات (Grant Tables)
* هي الجداول الداخلية الخاصة بنظام MySQL (الموجودة بداخل قاعدة بيانات `mysql` مثل `mysql.user`).
* تُخزن الحسابات وكلمات المرور والأذونات، ويقرأها MySQL عند تشغيل السيرفر ويضعها بداخل الذاكرة العشوائية (RAM) لسرعة التحقق من الصلاحيات.

---

### 8️⃣ متى يكون لديك كلمة مرور وكيف تتعامل مع شاشة طلبها؟
* **وجود كلمة المرور:** عند إنشاء الحساب بـ `caching_sha2_password` أو `mysql_native_password` عبر أمر `CREATE USER ... IDENTIFIED BY 'pass'`، أو عند تعديل الحساب بـ `ALTER USER`. أما مع `auth_socket` فلا توجد كلمة مرور.
* **عند ظهور `Enter password:`:**
  * إذا كتبت `mysql -u root -p` والحساب بـ `auth_socket`؛ اضغط `Enter` وسيظهر `Access Denied` لأن الدخول يلزم `sudo`.
  * إذا كتبت `sudo mysql`؛ كلمة المرور المطلوبة هي **كلمة سر حسابك بـ Linux** (ولن تظهر أحرف أو نجوم أثناء كتابتها لأسباب أمنية).

---

### 9️⃣ استعادة وتغيير كلمة المرور المنسية
* لا يمكن معرفة كلمة المرور القديمة كنص واضح لأنها مشفرة (Hashed).
